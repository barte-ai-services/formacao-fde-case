Três regras da stack

Só o Worker fala com o banco.RLS ligado em toda tabela e nenhuma política: a chave pública não lê nada. O navegador e o MCP passam pela API.
Dados fiscais no Brasil.O cliente exige. O Supabase fica em São Paulo e serve só de banco e storage, sem o Auth dele.
O mock troca sem dor.Um conector por sistema, todos com a mesma interface. Trocar a base do kit pela fonte real muda só o conector.

Peça a peça

Tela e Access

Um Worker com React. O Access fica na frente: entra quem tem o e-mail liberado, com código por e-mail ou SSO.

# criar e publicar
npm create cloudflare@latest -- ja-chegou-web --framework=react
cd ja-chegou-web
npx wrangler deploy

# no painel: Zero Trust › Access › Applications
# a API confere o cabeçalho Cf-Access-Jwt-Assertion
npm install jose

API com Cron

Um Worker em TypeScript com as rotas da tela e um Cron Trigger para o que roda sozinho.

npm create cloudflare@latest -- ja-chegou-api --type=hello-world --ts

// wrangler.jsonc
"triggers": { "crons": ["0 * * * *"] },
"ai": { "binding": "AI" }

// src/index.ts
export default {
  async fetch(req, env) { /* rotas da tela */ },
  async scheduled(controller, env, ctx) { /* o que roda sozinho */ },
} satisfies ExportedHandler<Env>;

npx wrangler dev
npx wrangler deploy

Claude e Clef

O Claude pelo SDK oficial, com a saída validada por um esquema. O Clef pelo binding do Workers AI.

npm install @anthropic-ai/sdk zod
npx wrangler secret put ANTHROPIC_API_KEY

import Anthropic from "@anthropic-ai/sdk";
import { zodOutputFormat } from "@anthropic-ai/sdk/helpers/zod";

const client = new Anthropic({ apiKey: env.ANTHROPIC_API_KEY });
const r = await client.messages.parse({
  model: "claude-opus-5-5",
  max_tokens: 16000,
  messages: [{ role: "user", content: pergunta }],
  output_config: { format: zodOutputFormat(Esquema) },
});
r.parsed_output;  // null se não validou

// Clef: o id do modelo está no catálogo do Workers AI
await env.AI.run(MODELO_CLEF, entrada);

Servidor MCP

Opcional. Um Worker que expõe tools ao Claude Code e chama a API, nunca o banco.

npm create cloudflare@latest -- ja-chegou-mcp \
  --template=cloudflare/ai/demos/remote-mcp-authless
npx wrangler deploy

# ligar no Claude Code, no escopo local (o padrão)
claude mcp add --transport http ja-chegou \
  https://ja-chegou-mcp.<subdominio>.workers.dev/mcp

Supabase em São Paulo

Banco e storage. O projeto nasce em sa-east-1, e o esquema vive em migrações no fork.

npx supabase projects create ja-chegou --region sa-east-1
npx supabase init
npx supabase migration new esquema_inicial
npx supabase link
npx supabase db push

-- em toda tabela: RLS ligado, nenhuma política
alter table public.minha_tabela enable row level security;

# só a API guarda a chave secreta
npx wrangler secret put SUPABASE_SECRET_KEY

GitHub Actions

Depois do merge na main, publicam os Workers e aplicam as migrações. Só isso.

gh secret set CLOUDFLARE_API_TOKEN
gh secret set CLOUDFLARE_ACCOUNT_ID
gh secret set SUPABASE_ACCESS_TOKEN
gh secret set SUPABASE_DB_PASSWORD

# actions: cloudflare/wrangler-action e supabase/setup-cli

Políticas de RLS

Regras no próprio Postgres sobre quem lê e quem altera cada linha, lidas do JWT de quem chama.

Mais de um cliente chamar o banco direto, como o navegador ou o MCP, e o banco precisar recusar o que não cabe a cada um.
